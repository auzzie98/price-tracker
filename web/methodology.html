Methodology

How prices are tracked

One observation is one scraped data point: timestamp, SKU, retailer, price, in-stock flag, and source URL. Prices are stored in cents as an integer in the database. Display shows dollars on the site.

Median price per SKU

For each SKU and period, the median price is calculated across all in-stock retailers. Out-of-stock listings are ignored for the median calculation. If a SKU has no in-stock price in a period, it has no sku_prices row for that period — a zero price is never written.

Index calculation

The index uses a chained, equal weighted, matched model, starting at 100. The model works as follows:

  • Each period, only SKUs priced in both the current period and the previous period are used (matched model).
  • For each common SKU, the price relative is calculated as current price divided by previous price.
  • The average of all price relatives gives the period's adjustment factor.
  • The index is chained: each period's index value is the previous period's index multiplied by the average relative, rounded to 2 decimal places.
  • A new SKU is left out of the index until it has its own history. It counts from its second period, through its own change only.

Out-of-stock rule

If a SKU has no in-stock observation for 7 consecutive days, it leaves the basket (no sku_prices row, no index contribution). When the SKU returns with an in-stock price, it re-enters from its second period after return, following the matched model rule. This prevents a single out-of-stock period from permanently removing a SKU while also preventing stale out-of-stock data from driving the index indefinitely.

Cold start

Charts begin at launch and history accumulates from day one. There is no backfill in v1. The first data point starts the history; subsequent periods add to it.

Revision rule

If a rebuild changes published numbers, the site must say so, with the dates affected and the reason. See the methodology page for the current rule.
